## Collection method

Generated by the CipherScope lab (M1) + capture (M2): the 16-profile strongSwan
matrix × 7 traffic types × 5 repetitions. Manifests carry ground truth from the
profile that produced each session; save-keys files decrypt captures offline to
verify inner-traffic labels (mvp.md §3.2). Baseline (non-VPN) captures of the
same traffic types are included to train/validate the "IPsec present / absent"
decision and to show the metadata encryption removes (§3.2).

## Target size

**≥ 16 profiles × 7 traffic types × 5 repetitions ≈ 560 sessions**, about
5–15 GB of PCAP, more than 100 k labeled flow windows (mvp.md §7).
Public captures (ISCX VPN-nonVPN 2016, CIC) can be added for extra testing (§7, §12).

## Schema

- `labels.csv`: `session_id, profile, traffic_type, ike_version, mode, enc, key_bits,
  integ, dh_group, pfs, nat_t, child_rekey_s, replay_window` (mirrors the §3.2 manifest).
- `features/flow_windows.parquet`: one row per 5 s window per SA (§3.3 features).
- `features/sa_evidence.parquet`: one row per SA.
- `splits/`: session ids grouped **by profile** so test profiles are unseen (§3.4).

## Class balance

7 traffic classes (icmp, web, email, voip, video, messaging, bulk) × balanced
profile coverage; the `bulk` class is the negative/control class (§3.1).
Exact counts land here after the first `make dataset` run.
